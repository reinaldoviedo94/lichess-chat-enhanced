### 2.2 SSL / 525 (lección clave)
La zona es **Full/Strict** → con `certificate_id=0` (siempre flexible) el droplet devuelve 525.
Solución:
- Cert LE real emitido con certbot `/dns-cloudflare` (**DNS-01**, token CF del usuario), CN `lce.casahidroneumatica.com.co`, subido a NPM como **cert id=8** (`provider=other`, expira **Dec 27 2026**).
- **Campos multipart de NPM al subir PEM**: `certificate=@fullchain.pem` + `certificate_key=@privkey.pem` (**NO** `private_key` → daba 500 "Received undefined").
- **Actualizar `certificate_id` por PUT NO regenera nginx**: hay que **borrar y recrear el host** proxy (esto puso `nginx_online=True`).
- Es normal que el navegador vea el cert edge de Cloudflare (CN=`casahidroneumatica.com.co`); lo importante es que Cloudflare→NPM use el LE (sin 525).

### 2.3 CORS (issue #3, cerrado)
- En prod `CORS_ALLOW_ALL_ORIGINS=false` (antes el deploy forzaba `true`).
- Verificado: petición con `Origin: https://evil.example.com` → 200 **sin** `Access-Control-Allow-Origin`.
- La extensión **no se rompe** por CORS cerrado: usa `host_permissions` (MV3 salta CORS) y la página de descarga es same-origin.

## 3. CI/CD

Workflows en `.github/workflows/`:
- **`ci.yml` (CI)**: backbone + frontend. Triggers: push a `develop|main|master`, PR.
  - Backend: `pip install .` + `python manage.py test` (9/9 OK) con `DJANGO_DEBUG=true` y `DJANGO_SECRET_KEY` de CI.
  - Frontend: `pnpm tokens:check` + `pnpm test:unit` (`node --test src/lib/*.test.mjs`) + `pnpm build`.
  - **Fixes aplicados**: trigger incluye `develop` (antes solo main/master → 0 runs); `cache-dependency-path` apunta al `pnpm-lock.yaml` del subdir; descubrimiento de paquetes explícito en `pyproject.toml` (§5).
- **`deploy.yml` (Deploy)**: push a `develop` → build imagen GHCR pública (sin login) + package zip de la extensión con `API_BASE` horneado (secret) + scp/ssh a droplet + healthcheck.
- **`pages.yml` (GitHub Pages)**: push a `develop` → publica `docs/` (índice + diagramas Archify).

### Flatten del bundle (bug superado)
`scp-action` anida fuentes en `target/tmp`. El script de flatten **solo movía `tmp/*` si el directorio estaba vacío** → en el **segundo deploy** el zip nuevo quedaba atrapado en `tmp/` y se servía el viejo. Fix: `cp -f extension/tmp/* extension/` + `rm -rf extension/tmp` incondicional. Verificado end-to-end.

## 4. GitHub secrets (nombres; valores vía `gh secret set`)

```
API_BASE                  = https://lce.casahidroneumatica.com.co/api
CORS_ALLOWED_ORIGINS
DJANGO_ALLOWED_HOSTS      (incluye 127.0.0.1, localhost, y el dominio)

DO_SSH_KEY
APPS_HOST                 (do-apps)
PUBLIC_ORIGIN             = https://lce.casahidroneumatica.com.co
```
- **`API_BASE` via secret → CI/CD**: la extensión MV3 no lee env en runtime; webpack `DefinePlugin` hornea `__LCE_API_BASE__` en build-time. Local sin env → `http://127.0.0.1:8000/api`; en CI → el secret. La extensión empaquetada (la que sirve el zip) apunta al backend público → dos oponentes pueden registrarse/loguearse en prod.
- NPM/CF/tokens: **no guardados en texto plano**; existen en el entorno del usuario.

## 5. Configuración clave del backend

`services/lichess_chat_enhanced/` (Django). Env-driven en `settings.py`:
`DJANGO_SECRET_KEY`, `DJANGO_DEBUG`, `DJANGO_ALLOWED_HOSTS`, `CORS_ALLOWED_ORIGINS`, `PUBLIC_ORIGIN`, `DB_PATH`, `MEDIA_ROOT`, `EXTENSION_DIR`, `EXTENSION_ZIP_NAME`, `SECURE_PROXY_SSL_HEADER`/`USE_X_FORWARDED_HOST` (para NPM).

- **SIMPLE_JWT**: ACCESS 1h, REFRESH **30 días**, `ROTATE_REFRESH_TOKENS=True`, `BLACKLIST_AFTER_ROTATION=False` → el login persiste en `chrome.storage.local` (refresh automático en `authFetch`). Login única vez por diseño.
- Apps/packs: `emojis/` (management command `seed_demo_packs.py`); auth: `accounts/` (register/login/token-refresh/me).
- **`pyproject.toml`**: descubrimiento de paquetes explícito (`accounts*`, `emojis*`, `lichess_chat_enhanced*`); exclude `docker*`, `templates*`, `media*`. Sin esto `pip install .` falla por flat-layout.

### Nota venv local
El `.venv` del backend es de **uv** → no tiene `pip`. Para probar `pip install .` como CI, usar un venv limpio (`/usr/bin/python3 -m venv`), no el `.venv`.
